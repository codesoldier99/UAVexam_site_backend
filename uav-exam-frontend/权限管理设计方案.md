# 无人机考试管理系统 - 权限管理设计方案

## 📋 当前系统权限管理现状分析

### 1. 现有权限检查机制
从代码中可以看到，系统已经有基础的权限框架：

**用户角色定义**：
- `super_admin` - 超级管理员
- `admin` - 考务管理员（系统管理员）
- `operator` - 操作员用户（培训机构）
- `examiner` - 考官
- `candidate` - 考生

**权限检查方法**：
```typescript
// 在 stores/user.ts 中
hasPermission(permissions: string[] | undefined): boolean {
  if (!permissions || permissions.length === 0) return true
  if (!this.userInfo?.role) return false
  
  // super_admin 拥有所有权限
  if (this.userInfo.role === 'super_admin') return true
  
  return permissions.includes(this.userInfo.role)
}
```

**路由权限控制**：
```typescript
// 在路由配置中
meta: {
  requiresAuth: true,
  permissions: ['admin', 'super_admin']
}
```

**模板权限指令**：
```html
<!-- 在模板中使用 -->
<el-button v-permission="['admin']">管理员功能</el-button>
```

### 2. 详细权限设计

#### 2.1 超级管理员 (super_admin)
**权限范围**：系统所有功能
- ✅ 系统设置：所有配置项（基本设置、安全设置）
- ✅ 用户管理：创建/删除考务管理员和机构用户账户
- ✅ 系统监控与日志查看
- ✅ 权限分配管理
- ✅ 所有业务功能的完全访问权限
- ✅ 高级系统配置和维护功能

**核心职责**：
- 系统架构和安全管理
- 用户账户管理（考务管理员、机构用户）
- 系统配置和监控
- 权限体系维护

#### 2.2 考务管理员 (admin)
**权限范围**：考务业务管理功能
- ✅ 考试产品管理：创建、编辑、删除考试产品（如"多旋翼视距内驾驶员"）
- ✅ 考场资源管理：管理考点内的物理场地（理论教室、实操场地、候考场）
- ✅ 考务排期：为已报名考生安排具体考试日程，支持按机构分组排期
- ✅ 人员管理：管理考官和考生信息
- ✅ 签到管理：查看和管理所有签到记录
- ✅ 数据统计：查看所有统计报表
- ✅ 基础系统设置：基本信息配置等

**限制**：
- ❌ 不能修改系统核心安全设置
- ❌ 不能创建/删除管理员账户
- ❌ 不能访问系统日志和监控
- ❌ 不能修改权限配置
- ❌ 不能直接为考生报名（由机构用户负责）

**核心职责**：
- 考试产品和考场资源配置
- 考务排期和日程安排
- 考试流程管理
- 人员信息维护
- 业务数据统计

#### 2.3 机构用户 (institution)
**权限范围**：考生报名管理功能
- ✅ 考生报名管理：为本机构考生进行报名（批量导入和手动录入）
- ✅ 报名模板下载：下载标准的考生信息Excel模板
- ✅ 批量导入：上传填写好的Excel文件进行批量报名
- ✅ 手动录入：通过表单界面逐一输入考生信息
- ✅ 考生信息查看：查看本机构已报名考生的信息和状态
- ✅ 考试安排查看：查看本机构考生的考试排期
- ✅ 签到记录查看：查看本机构考生的签到情况
- ✅ 机构统计：查看本机构的考试统计数据

**限制**：
- ❌ 只能管理本机构的考生
- ❌ 不能查看其他机构的信息
- ❌ 不能修改考试产品和考场资源
- ❌ 不能进行考务排期
- ❌ 不能访问系统设置

**核心职责**：
- 本机构考生报名管理
- 考生信息维护
- 报名数据录入和导入
- 机构考试数据查看

#### 2.4 考官 (examiner)
**权限范围**：监考相关功能
- ✅ 考试管理：查看分配给自己的考试
- ✅ 考生管理：查看参与考试的考生信息
- ✅ 签到管理：记录和管理负责考试的签到
- ✅ 考勤统计：查看自己负责考试的考勤统计
- ✅ 个人信息：修改自己的基本信息
- ✅ 考场信息：查看考试相关的考场信息

**限制**：
- ❌ 只能查看和操作分配给自己的考试
- ❌ 不能创建或删除考试
- ❌ 不能管理其他考官信息
- ❌ 不能访问系统设置
- ❌ 没有成绩录入功能

**核心职责**：
- 监考执行
- 考生签到管理
- 考试现场管理
- 考勤记录维护

#### 2.5 考生 (candidate)
**权限范围**：个人相关功能
- ✅ 考试信息：查看管理员安排的考试信息
- ✅ 个人信息：查看和修改自己的基本信息
- ✅ 考试记录：查看自己的考试历史和成绩
- ✅ 签到记录：查看自己的签到记录
- ✅ 考场信息：查看考试的考场信息

**限制**：
- ❌ 只能查看和操作自己的信息
- ❌ 不能查看其他考生信息
- ❌ 不能访问管理功能
- ❌ 不能查看系统统计数据
- ❌ 没有证书下载功能
- ❌ 不能自主报名（报名由机构用户负责）

**核心职责**：
- 查看考试安排信息
- 个人信息维护
- 成绩查询
- 签到记录查看

### 3. 权限实现方案

#### 3.1 前端权限控制

**路由级权限**：
```typescript
// 路由配置示例
{
  path: '/exam/list',
  component: ExamList,
  meta: {
    requiresAuth: true,
    permissions: ['super_admin', 'admin', 'examiner'], // 允许的角色
    action: 'read' // 操作类型：read, write, delete
  }
}
```

**组件级权限**：
```typescript
// 权限指令增强
v-permission="{ roles: ['admin'], action: 'write' }"
v-permission="{ roles: ['examiner'], resource: 'own_exams' }"
```

**API级权限**：
```typescript
// 在API调用前检查权限
const canCreateExam = userStore.hasPermission(['admin', 'super_admin'], 'write')
if (!canCreateExam) {
  ElMessage.error('没有权限执行此操作')
  return
}
```

#### 3.2 后端权限验证

**中间件权限检查**：
```python
# 后端权限装饰器示例
@require_permissions(['admin', 'super_admin'])
@require_action('write')
def create_exam():
    pass

@require_permissions(['examiner'])
@require_resource_access('own_exams')
def get_examiner_exams():
    pass
```

#### 5.2 动态权限检查
```typescript
// 增强的权限检查方法
hasPermission(resource: string, action: string, resourceId?: number): boolean {
  const userRole = this.userInfo?.role
  const userId = this.userInfo?.id
  
  // 检查基础角色权限
  const allowedRoles = PERMISSIONS[resource]?.[action]
  if (!allowedRoles?.includes(userRole)) return false
  
  // 检查资源级权限（如：考官只能操作自己负责的考试）
  if (resourceId && userRole === 'examiner') {
    return this.checkResourceAccess(resource, resourceId, userId)
  }
  
  return true
}
```

### 7. 实施建议

#### 7.1 优先级实施顺序
1. **高优先级**：完善路由权限控制
2. **中优先级**：实现组件级权限显示/隐藏
3. **低优先级**：实现细粒度的数据权限过滤

#### 7.2 用户体验优化
- 无权限的功能按钮显示为禁用状态，而不是隐藏
- 提供清晰的权限不足提示信息
- 为不同角色提供定制化的导航菜单
- 考官登录后直接显示分配给自己的考试
- 考生登录后直接显示考试信息（报名功能由其他软件提供）

#### 7.3 安全考虑
- 前端权限控制主要用于用户体验，真正的安全验证在后端
- 敏感操作需要二次确认
- 记录所有权限相关的操作日志
- 签到操作需要验证时间和地点限制

#### 9.1 登录验证流程
```
用户登录 → 验证账号密码 → 获取用户角色 → 生成JWT令牌 → 返回用户信息和权限
```

#### 9.2 页面访问验证流程
```
访问页面 → 检查登录状态 → 验证路由权限 → 检查角色权限 → 允许/拒绝访问
```

#### 9.3 操作权限验证流程
```
执行操作 → 检查功能权限 → 验证资源权限 → 记录操作日志 → 执行/拒绝操作
```
