# 手动签到接口测试说明

## 测试脚本说明

### 1. test_manual_checkin.py - 交互式测试脚本

**功能**: 提供交互式界面，可以手动输入测试数据进行测试

**使用方法**:
```bash
python test_manual_checkin.py
```

**测试模式**:
- **完整流程测试**: 测试查询→确认的完整签到流程
- **仅查询测试**: 只测试查询考生信息接口
- **仅确认测试**: 只测试确认签到接口

### 2. test_manual_checkin_batch.py - 批量测试脚本

**功能**: 自动化批量测试多种场景和边界条件

**使用方法**:
```bash
python test_manual_checkin_batch.py
```

**测试场景**:
- 正常考生查询
- 不存在的考生
- 姓名身份证不匹配
- 空值验证
- 权限验证

## 测试前准备

### 1. 修改配置

在测试脚本中修改以下配置：

```python
# 后端服务地址
BASE_URL = "http://localhost:8000"  # 修改为实际地址

# 测试用户凭据（必须是考务人员角色）
TEST_USERNAME = "admin"     # 修改为实际用户名
TEST_PASSWORD = "password"  # 修改为实际密码
```

### 2. 准备测试数据

在数据库中准备一些测试数据：
- 至少一个考务人员账号（ADMIN/SUPER_ADMIN/EXAMINER角色）
- 至少一个考生账号，包含：
  - 真实姓名
  - 身份证号
  - 考试安排（Schedule）
  - 考试时间在合理范围内

### 3. 启动后端服务

确保后端服务正在运行：
```bash
cd backend
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

## 测试接口详情

### 接口1: 查询考生信息
- **URL**: `POST /api/v1/wechat/manual-checkin/query`
- **权限**: 需要考务人员权限
- **请求体**:
```json
{
  "real_name": "考生姓名",
  "id_card": "身份证号"
}
```
- **响应**:
```json
{
  "candidate_info": {
    "id": 1,
    "real_name": "张三",
    "id_card": "110101199001011234"
  },
  "exam_schedules": [
    {
      "schedule_id": 1,
      "exam_name": "无人机驾驶员考试",
      "venue_name": "考场A",
      "exam_date": "2025-08-28",
      "start_time": "09:00",
      "end_time": "11:00",
      "can_checkin": true,
      "checkin_status": "未签到"
    }
  ]
}
```

### 接口2: 确认手动签到
- **URL**: `POST /api/v1/wechat/manual-checkin/confirm`
- **权限**: 需要考务人员权限
- **请求体**:
```json
{
  "candidate_id": 1,
  "schedule_id": 1,
  "operator_info": "工作人员(张老师)"
}
```
- **响应**:
```json
{
  "success": true,
  "message": "签到成功",
  "checkin_info": {
    "checkin_id": 123,
    "checkin_time": "2025-08-28T08:30:00",
    "method": "MANUAL",
    "operator": "工作人员(张老师)"
  }
}
```

## 常见测试场景

### 1. 成功场景
- 使用有效的考生姓名和身份证
- 在签到时间窗口内（考试前30分钟到考试结束）
- 考生尚未签到

### 2. 失败场景
- 考生不存在
- 姓名与身份证不匹配
- 不在签到时间窗口内
- 考生已经签到过
- 没有考务人员权限

### 3. 边界条件
- 空字符串输入
- 特殊字符输入
- 超长字符串
- 无效的ID格式

## 测试结果分析

### 状态码说明
- **200**: 请求成功
- **400**: 业务逻辑错误（如考生不存在、已签到等）
- **401**: 未认证
- **403**: 权限不足
- **422**: 请求参数验证失败

### 日志查看
测试时可以查看后端日志来了解详细的执行过程：
```bash
# 查看后端日志
tail -f backend/logs/app.log
```

## 注意事项

1. **权限要求**: 测试用户必须具有考务人员权限
2. **时间窗口**: 签到有时间限制，确保测试时间合理
3. **数据准备**: 确保数据库中有合适的测试数据
4. **网络连接**: 确保能正常访问后端服务
5. **重复测试**: 同一考生同一场次只能签到一次

## 故障排除

### 1. 登录失败
- 检查用户名密码是否正确
- 确认用户角色是否为考务人员
- 检查后端服务是否正常运行

### 2. 查询无结果
- 确认考生数据是否存在
- 检查姓名和身份证是否完全匹配
- 确认考生是否有考试安排

### 3. 签到失败
- 检查是否在签到时间窗口内
- 确认考生是否已经签到过
- 检查考试安排状态是否正常

### 4. 权限错误
- 确认登录用户角色
- 检查token是否有效
- 确认接口权限配置
